Skill
是什么？

Skill（技能）是打包给 Agent 的"操作手册"：一个带 SKILL.md 说明文件的文件夹，写清这类任务该怎么做、有什么坑、附哪些脚本和资料——Agent 遇到相关任务时才按需加载。一句话：MCP 给它工具，Skill 给它手艺。

比如团队有一套"周报怎么写"的固定格式。每次让 AI 重新解释一遍？不如做成一个 Skill：任务一相关，Agent 自动翻出这份手册——格式、禁忌、范文全在里面。你本地装的那二十多个 lark skill（读文档、发消息、查日历），就是这套机制的真实样例。

为什么重要

工具决定它能不能做，
技能决定它做得像不像样。

同一个 Agent，装不装技能是两种东西：没有技能，它每次都要你从头教，做得"对但难看"；装上技能，它带着团队的沉淀上岗，第一次出手就像老师傅。官方把这叫"给智能体装备真实世界的能力"——本质是把流程知识从人脑和散落的文档里，搬进机器可执行、可分发的手册。

一门手艺的编年史

  • 2024 前身散落

    提示词模板与"项目说明书"约定（如 CLAUDE.md）在各工具里各自出现——"给 AI 喂手册"已被证明有效，缺的是统一格式。

  • 2025 · 10 Agent Skills 发布

    Anthropic 正式发布 Agent Skills：SKILL.md 定义格式，Claude 应用、Claude Code 与 API 全面支持。

  • 2025 · 12 开放标准

    Anthropic 将 Agent Skills 开放为跨平台标准——技能不再绑定 Claude 一家，像 MCP 一样走向通用。

  • 2026 生态繁荣

    各家 Agent 产品支持技能机制；skills CLI 与目录站让"装技能"像装插件一样简单；企业开始建内部技能库。10 月，Anthropic 将 Agent Skills 标准捐赠给中立组织 Agentic AI Foundation 维护。

设计张力与常见误解

  • 通用 vs 私有——公开技能普惠生态，私有技能沉淀手艺；敏感流程建议留在内部仓库。
  • 手写 vs 生成——可以让 AI 帮你起草技能，但流程里的"坑"只有真做过的人知道。
  • 多 vs 精——技能装太多、命名含糊，触发就会互相干扰；单一职责、描述清楚。
  • 静态 vs 进化——技能像代码一样要维护：流程变了不改 SKILL.md，它就教错下一代。
  • 便利 vs 安全——第三方技能的内容会进入 Agent 上下文，提示注入是真实风险；装前先读。
  • 知识 vs 脚本——纯说明就能解决的手艺不必硬塞脚本；脚本用于"必须精确执行"的步骤。

三个常见误解：① "Skill = 插件/工具"——工具让它"能做"（MCP），技能让它"做得对"（流程知识），两者常搭配；② "写 Skill 要会编程"——SKILL.md 就是 Markdown，会写文档就会写；③ "装得越多越强"——技能也要单一职责、描述精准，堆数量只会互相干扰。

常见问题

Skill 和 MCP 有什么区别？+
分工不同：MCP 管连接——把日历、文档、数据库这些"能力"插给 Agent；Skill 管方法——把"这类活儿怎么做"的流程知识教给 Agent。经典组合是两者都用：Skill 里的步骤指引 Agent 去调 MCP 提供的工具。
它和提示词工程是什么关系？+
技能就是沉淀下来的提示工程：你在对话里反复解释的那套要求，写成 SKILL.md 固化下来，以后不用再解释。姊妹篇 Prompt 工程里的六行骨架，正是技能正文的写作基础。
需要会编程吗？+
不需要。SKILL.md 就是 Markdown 文档——一个名字、一段"什么时候用"、一组步骤与禁忌，就是一门合格的技能。只有当流程需要精确执行（如批量处理）时，才值得捆绑脚本。
怎么写我的第一个 Skill？+
三行起步（见页尾模板）：给它起个清晰的名字；description 写清楚"什么任务该用它"——这是 Agent 决定是否加载的唯一依据；正文写步骤、禁忌和一份范文。放进技能目录即可生效。
团队怎么共享技能？+
把技能文件夹放进 git 仓库：版本可追溯、评审走 PR、新人一行命令安装。企业内部流程（报销怎么审、周报怎么写、发布怎么检查）都适合做成内部技能库——这是 2026 年很流行的"知识资产化"。
装别人的技能安全吗？+
技能内容会进入 Agent 上下文，恶意技能可以夹带提示注入——风险是真的。装前三步：读一遍 SKILL.md 全文、看发布方与使用量、优先官方与高可信来源；捆绑了脚本的更要逐行看。
