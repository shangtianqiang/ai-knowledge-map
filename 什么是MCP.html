MCP
是什么？

MCP（Model Context Protocol，模型上下文协议）是 Anthropic 在 2024 年 11 月开源的连接标准：在 AI 应用与外部世界之间定义一个统一的插头——数据、工具、服务即插即用。业界叫它"AI 的 USB-C"。

在它出现之前，M 个模型接 N 个工具要写 M×N 套接口，组合爆炸；有了 MCP，工具方实现一次协议，所有支持它的 AI 都能用。2025 年 3 月，OpenAI 也宣布采用——竞争对手变成了共建者。

为什么重要

接口统一的那一刻，
生态才开始滚雪球。

MCP 的洞见不在技术复杂度，而在时机与开放：AI 能力在飞速上涨，"连接"却还是各家私有接口。一个中立、开源、不锁厂商的协议，让最激烈的竞争者愿意共建—— Model Context Protocol 赢的不是某家模型，而是"所有模型 + 所有工具"这个更大的盘子。

01

组合爆炸的解药

M 个模型 × N 个工具，从 M×N 套私有适配变成 M+N 套标准实现——数学变了，生态的 economics 就变了。

02

双向的安全连接

不止"读取数据"：工具调用、参数传递、结果回传、逐次审批都有约定——它是为"AI 要动手"的时代设计的。

03

生态的公共底座

Server 写一次，处处可用；协议开源、厂商中立。连接层不再是谁的护城河，而是所有人脚下的公路。

一个协议的四步

  • 2024 · 11 发布

    Anthropic 开源 MCP 与首批 SDK、官方 server（GitHub、Slack、Google Drive 等），把"AI 怎么连工具"变成一个标准问题。

  • 2025 · 3 竞对采用

    OpenAI 宣布 Agents SDK 支持 MCP；TechCrunch 报道标题：《OpenAI adopts rival Anthropic's standard for connecting AI models to data》。

  • 2025 · 全年 生态爆发

    官方与社区 server 数量激增，Google DeepMind、Microsoft 等相继表态支持（第三方报道）；MCP 成为招聘与产品发布里的高频词。

  • 2026 事实标准

    "支持 MCP"成为 AI 应用连接能力的默认选项；讨论重心从"接什么"转向安全、身份与治理——非人类身份管理成为新议题。

设计取舍与常见误解

  • 开放 vs 安全——标准越通用，恶意 server 与提示注入的面越大；装第三方 server 前先看来源与权限。
  • 本地 vs 远程——stdio 模式数据基本不出机器，远程 HTTP 换来便利与共享；按数据敏感度选择。
  • 标准 vs 性能——中间层有开销，直连 API 更快；但通用性与可维护性通常值得这点溢价。
  • 官方 vs 社区——server 目录繁荣但质量参差；优先官方实现与高星项目，读一下它申请的权限。
  • 全权 vs 审批——给 host 的权限越大，MCP 越像"双手"；审批策略要跟上（呼应姊妹篇 Harness）。
  • 协议 vs 产品——MCP 只管"怎么连"，不管"连上之后多聪明"；体验仍取决于模型与 harness 的设计。

三个常见误解：① MCP 不是模型——它不参与推理，只负责搬运"能力与数据"；② MCP 不是 API 的替代品——很多 server 底层仍在调 API，它标准化的是"AI 如何发现并使用这些能力"；③ "支持 MCP"不等于"自动安全"——插头统一了，篱笆还得自己扎。

常见问题

MCP 和 Function Calling 有什么区别？+
Function calling 是"模型说想调哪个函数"的模型侧机制；MCP 是"函数从哪来、怎么被发现、怎么授权"的连接标准。可以理解为：MCP 用 Function calling 这块积木，搭出了一个可插拔的工具市场。
我需要会写代码才能用吗？+
用，不需要：主流 AI 应用（Claude、Cursor 等）在设置里添加 server 即可，社区还有现成目录。开发 server 才需要编码——官方 SDK 已把它做得很薄，一个天气查询的 quickstart 一杯咖啡时间就能跑通。
MCP server 会看到我的什么数据？+
取决于你接了什么、授了什么权：本地 stdio 模式数据基本不出机器；远程 server 要读它的隐私政策与部署方。原则两条：最小授权 + 优先可信来源，敏感场景选本地实现。
为什么 OpenAI 要采用对手的标准？+
因为生态价值大于控制欲：工具方不会为每个模型重复开发，用户不想被锁死。协议中立时，采纳它比另起炉灶便宜——这正是"事实标准"的诞生方式：不是谁下令，而是人人都省了一笔账。
MCP 和 Agent 是什么关系？+
MCP 解决"能力从哪来"，Agent / Harness 解决"能力怎么被有纪律地使用"。本系列姊妹篇里说的"给 Agent 的那双手"，很多手指头就是 MCP 插上的——两者是插头与手的关系。
安全吗？装之前看什么？+
看三样：来源可信度（谁写的、多少人用）、权限清单（它声明要读写什么）、审批机制（每次调用是否要你确认）。再配合 host 侧的审批与沙盒——协议是开放的花盆，篱笆还得自己扎。
