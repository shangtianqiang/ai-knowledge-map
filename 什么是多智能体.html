多智能体
是什么？

多智能体（Multi-agent）是让多个 Agent 分工协作：主 Agent 拆解任务、派发给子 Agent，各自带着干净的上下文独立执行，再汇总结果。一句话：组队买的不是更聪明，是分治与并行。

深度研究产品就是标准多智能体：规划员拆问题、多个搜索员并行查证、写作员汇总成稿——单 Agent 串行要一小时，组队十分钟出结果（效果描述以各家产品为准）。

为什么重要

组队不是让 AI 更聪明，
是让问题被切成能吞下的小块。

单 Agent 的瓶颈常是上下文：任务一复杂，窗口被过程填满、注意力被稀释。多智能体用"隔离"换"专注"——每个子 Agent 拿到干净窗口只干一件事。但编排本身也是成本：传话会失真、错误会级联、token 会乘法增长——先跑通单 Agent，再考虑组队。

01

分治换上下文

任务拆开后，每个子 Agent 的窗口只装自己那件事，注意力不再被过程稀释——隔离是组队最大的红利。

02

编排是产品设计

拆多细、任务描述怎么写、结果怎么汇总校验——全是产品决策。多智能体的上限在编排设计，不在模型参数。

03

成本是乘法

N 个子 Agent 各烧各的窗口：官方自述研究场景 token 约为单次聊天的 15 倍——组队要花在高价值任务上。

设计张力与常见误解

  • 单 vs 多——默认单 Agent：更稳、更省、更好调试；任务可并行且需要专业分治时才组队。
  • 通用 vs 专业子 Agent——一个全能 worker 省心，多个专家各带自己的上下文与工具更准。
  • 同步等待 vs 异步并行——等全部完成再汇总（稳），还是先到先用（快）——决定产品的手感。
  • 透明 vs 失控感——展示"谁在干什么"让人放心，也暴露了系统的复杂度。
  • 效率 vs 成本——并行省的是时间，烧的是 token；快和省很少两全。

三个常见误解：① "人多力量大"——Agent 越多，通信与失败面越大，收益常常递减；② "多智能体是更强的模型"——它是编排架构，不是模型升级，底座还是同一个 LLM；③ "组队自动更准"——传话失真与级联错误是真实代价，必须有汇总与校验环节兜底。

常见问题

什么时候需要多智能体？+
两个信号同时出现才值得：任务可并行（子问题彼此基本独立）且需要专业分治（每块要不同的上下文、工具或视角）。深度研究是典型样例；写一封邮件就不值得。拿不准就先跑单 Agent——组队是手段，不是目的。
和单 Agent 比，优势到底在哪？+
不在"更聪明"，在三件事：上下文隔离——每个子 Agent 拿干净窗口，过程噪音不回灌；并行加速——N 路同时查证；专业分治——各带各的工具与资料。官方数据显示深度研究这类任务效果显著提升，代价是 token 也显著上升。
子 Agent 会不会互相打架？+
会，但形态是"撞车"不是"吵架"：重复查同一份资料、结论互相矛盾、格式对不上。解法都在编排里——任务边界写清楚（各自查什么、不查什么）、汇总员负责冲突消解；辩论模式甚至能把"互怼"变成一道质检工序。
成本大概多少？+
Anthropic 工程博客自述：多智能体研究消耗约为单次聊天的 15 倍 token（单 Agent 约为 4 倍），本站未复测。经验法则：把组队花在高价值、可并行的任务上；低价值任务用单 Agent，甚至普通对话就够。
怎么调试？+
三件套：留痕——每个子 Agent 的任务描述与回传全部落盘；单点复跑——出错的那一步单独重放；先单后多——先确认每个角色单独能干对，再连成一条线。多数"多智能体 bug"追到根上，是任务描述写得含糊。
入门选什么框架？+
按口味选：想要"角色班子"式分工看 CrewAI；想要可控的图状态机看 LangGraph；想要对话式协作与实验自由度看 AutoGen。但更重要的问题是"要不要多智能体"——多数场景，单 Agent 加一条好的工具链就已经够了。
