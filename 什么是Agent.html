AI Agent
是什么？

AI Agent（智能体）是能自主完成任务的 AI 系统：给它一个目标，它自己规划步骤、调用工具、执行动作、根据反馈调整，直到把事办成——而不只是回你一段话。一句话：聊天机器人"会说"，Agent "会做"。

比如，对它说"把本周会议纪要整理成周报发给团队"：Agent 会自己查日历、读记录、写文档、发消息，中途遇到报错还会换条路再试——你只在关键处拍板。业内有个公式：Agent = 模型 + Harness，这个系列讲的就是等号右边。

为什么重要

Agent 不是更聪明的聊天机器人，
是一种新的软件形态。

传统软件的行为是程序员写死的；Agent 的行为是模型在运行时现场决定的——输入一个目标，输出一串真实世界的动作。这带来前所未有的灵活性，也带来新问题：怎么验证它做对了？怎么限制它能做什么？——于是有了 Harness（骨架与纪律）、MCP（插头）、Skill（手艺），本系列后半的每一页都是这个新形态的零件。

01

目标导向

你给结果，不给步骤。步骤由模型根据目标现场规划——这是它与传统自动化脚本的根本区别。

02

工具在手

说得出就做得到——前提是接了插头。读写文件、跑终端、调 API，能力边界由工具决定。

03

反馈闭环

会看结果、会纠错、会重试：执行失败的报错会回到模型手里，换条路再试——这是"跑通"的关键。

  • 2023 想象力爆发

  • 2024 工程化

  • 2025 落地元年

  • 2026 走向普及

    办公、浏览器、企业流程的 Agent 相继落地；治理与安全（审批、沙盒、审计）成为下一阶段的主议题。

设计张力与常见误解

  • 自治 vs 安全——放权越多效率越高，出事也越难拦；自治度要跟着风险走。
  • 灵活 vs 可预测——现场规划带来灵活，也带来不可复现；关键流程要留轨迹。
  • 单打 vs 团队——多智能体分工能干大活，通信与成本也是乘法；别为了多而多。
  • 通用 vs 垂直——通用 Agent 什么都能试，垂直 Agent 在窄场景更稳；先窄后宽。
  • 成本 vs 效果——每一步都是模型调用，Token 烧得比聊天快几个量级；先算账再上。
  • 演示 vs 生产——Demo 成功率与生产成功率隔着工程鸿沟；评测与兜底是护城河。

三个常见误解：① "Agent = 更聪明的聊天机器人"——形态不同：输出不是文字而是动作；② "Agent 越自动越好"——自治是旋钮，高危动作必须留人；③ "有模型就有 Agent"——没有工具、循环与安全件，它只是会说话（见姊妹篇 Harness）。

常见问题

Agent 和聊天机器人、智能助手有什么区别？+
看输出：输出文字的是聊天，输出动作的是 Agent。聊天机器人给你一段"怎么写周报"的建议；Agent 真的把周报写出来、发出去。传统"智能助手"（定个闹钟）能力固定，Agent 的步骤则由模型现场规划。
Agent 一定要用大模型吗？+
通常要——"现场规划"依赖模型的推理与泛化能力。写死的规则脚本不是 Agent（没有自主决策）。也可以混搭：大模型做大脑，小模型或规则做廉价判断。
Agent 会自己联网吗？+
看接了什么工具：接了搜索/浏览器就能，没接就不能。它的能力边界 = 工具边界——这正是 MCP（连接标准）与 Harness（工具层）存在的意义，见姊妹篇。
怎么开始用第一个 Agent？+
推荐从编码 Agent 入手（Claude Code、Codex 等）——任务可验证、环境在本地、出问题能看见。日常场景则可以给聊天产品接上 MCP server，让它从"说"升级到"做"。
Agent 安全吗？出错了怎么办？+
安全不是它的自带属性，要靠三件套：审批（高危动作等人确认）、沙盒（动作关进笼子）、日志（全程可审计），再加上最小授权原则。详见姊妹篇 Harness 的安全设计一节。
Multi-agent（多智能体）是什么？+
多个 Agent 分工协作：一个当"项目经理"拆任务，其他各自执行再汇总。好处是能干大活、上下文各自隔离；代价是通信与成本翻倍——先跑通单 Agent，再考虑组队。
